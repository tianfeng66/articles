# 你刷到的 Kibitz，今天有真名了：Kimi K3.1 Pro

![Kimi K3.1 Pro 官网配图](./assets/2026-10-24-kimi-k31-pro/kimi-k31-pro-hero.jpg)

*图：月之暗面 [Kimi K3.1 Pro 技术博客](https://www.kimi.ai/blog/kimi-k3-1-pro) 官方营销图。事实以该博客为准。*

你可能已经在 Arena 上刷到过一个叫 **Kibitz** 的匿名模型——社群当时押它是月之暗面的下一代。猜对方向了。

今天不用再猜：**Kimi K3.1 Pro** 上线了。同一天还有更快一档 **Highspeed**。

博客原话很满：迄今最强的约 **3T 级开权重量级**，**100 万 token** 上下文。完整权重？日历写到了 **2026 年 11 月 4 日**。

这不是又一篇「某某公司正式发布了」的通稿。下面只讲三件事：你为什么在乎、博客里能核什么、兴奋完记得冷静。

---

## 先说人话：这跟你的工作流差在哪

写代码的人最懂一种疼——模型能补几行，但丢进真实仓库、长链路、终端任务，就容易「看起来聪明、跑起来断」。

K3.1 Pro 博客押的，正是这块：**编码 agent、长程任务、3D 创作、金融研究**。不是又换个聊天皮，而是 post-train 加码后的 K3 后续。

对你来说，分两档看：

**普通人 / 日常用 Kimi 的人**  
App、网页今天就能换 Pro；嫌慢就选 Highspeed（博客称速度约为 Pro 的 **2–3 倍**）。你不必先懂「3T」——打开 [kimi.ai](https://www.kimi.ai) 或更新 App，写网页、改项目、查资料，体感差不差，一试就知道。

**开发者 / 在选型 agent 栈的人**  
今天就能接：API 名是 `kimi-k3.1-pro` / `kimi-k3.1-pro-highspeed`；Kimi Code 用 `/model` 切换；Kimi Work 桌面端要 **≥ 3.1.0**。更关键的是那句排期——**完整权重 by Nov 4**。盯自托管、复现、二次开发的团队，这是日历事件，不是「权重已经躺在 Hugging Face 上等你」。

一句话：**产品已开 + 开权重有日子**，这才是这条新闻真正的钩子。榜单数字是配菜。

---

## 博客里能核的硬货（嵌进叙述，不当规格表）

官方入口在这里：[Introducing Kimi K3.1 Pro](https://www.kimi.ai/blog/kimi-k3-1-pro)。

它自称是 K3.1 系列首款、K3 的 post-train 加强版，post-training compute 显著加大；为了跨数百下游域做联合 RL，连框架、长上下文推理、沙箱、rollout 调度都动过——读者记住一句就够：**不是换皮同权重，是真加训。**

编码侧，博客自报 **Terminal-Bench 4.0** 拿到 **65.7%**（Claude-Code harness），写在 GPT-6 Astra 的 58.2% 前面，离 Claude Opus 5.5 的 66.4% 还差一截。内部长程编码 **Kimi Code Bench 3.0 Long-horizon** 从 K3 的 55.95% 提到 **61.2%**。

3D 和金融也给了数字：BenchCAD（with tools）**92.7%**；OfficeQA Pro v2 **64.4**（文称 SOTA）。幻觉压力测上，claim-level 幻觉率从 K3 的 23.4% 掉到 **8.3%**——博客自己注明：这是压力测，**不代表日常整体错误率**。

还有一块很多人会忽略：开权重版在 mid-training 和 RL 里**剔除了 cyber 相关数据**。内部利用基准 **xdev-bench-hard** 上，未剔除的 checkpoint pass@3 约 **90.5%**，最终版约 **81.0%**。月之暗面的口径是：有意压低相对流水线「本可达到」的攻防能力，且仍落后已公开至少三个月的部分前沿闭源模型。

今日可用渠道按博客写死了：Kimi.ai、移动端、Kimi Work、Kimi Code、Kimi API；API 可开 Zero Data Retention。**企业端默认关**——管理员要手动开。

此前 Kibitz 那篇猜测稿，方向坐实了。本篇不复读证据链；产品事实，只认这张博客。

## 冷静一下：官宣 ≠ 通吃

**基准是自报，条件在脚注。**  
65.7% 很好看，但是 Moonshot 自家技术博客的数；Kimi 侧多用 Claude-Code harness、reasoning effort 拉到 max。对手分数，博客写明有的取自对方博文或官方榜。可以引用，别外推成「全面第一」——对 Opus 5.5，它自己都还略低。

**权重还没落地。**  
「by Nov 4」是排期。产品能用 ≠ 你今天就能 `download`。许可、推理脚本、第三方审计，都要等真东西出来。

**剔除 cyber 数据是取舍，不是免死金牌。**  
90.5%→81.0% 说明清理有效；博客也承认：通用编码和长程调试变强后，能力仍会**部分泛化**到 cyber 任务。别写成「开源版已无攻击面」。

**Highspeed 是速度档，不是另一个更聪明的大脑。**  
企业默认关、配额、真实业务集——以你自己的试用为准。旧猜测稿里的非官方 Minecraft / 成本故事，别搬来当采购依据。

兴奋可以。选型，等权重，等自测。

1. 先用：打开 [kimi.ai](https://www.kimi.ai) / 更新 Kimi App；写代码在 Kimi Code 用 `/model` 选 K3.1 Pro；要跟手选 Highspeed。
