# Fable 越来越强，视频模型还有未来吗？

Fable 5.2 发布后，X 上出现了一批“它做的视频”。有人放出能在浏览器里玩的游船演示，有人用代码搭出一座小城，也有人交出用三维软件渲染的动画片头。一个老问题被重新提起：视频模型还有没有未来？

这不是一个可以用“它只是写代码”轻轻带过的问题。

用户要的是能交付的作品，不是某种特定的生成原理。如果语言模型加上渲染器，就能把一部分视频做得足够好、修改起来更方便，那么它是不是原生视频模型，对这部分需求来说，可能根本不重要。

**视频模型真正要担心的，未必是自己被技术上彻底替代，而是用户越来越少需要直接打开它。**

## 它没有直接生成视频，但视频确实做出来了

先分清两件事。

Anthropic 的[官方规格](https://platform.claude.com/docs/en/models/fable-5-2/overview)仍把 Fable 5.2 的输出列为文本；[产品页](https://www.anthropic.com/claude/fable)则强调，它可以用代码创建仿真、动画和教育视频。它可以规划场景、编写程序，再交给浏览器、渲染器或三维软件生成画面。

这和直接采样生成连续视频，不是一回事。但不能因此说，这些作品就不算视觉生产力的进步。

Kevin Ngo 的[游船浏览器游戏演示](https://x.com/kevin_t_ngo/status/2119868968307695818)，就是传播较广的一例。作者称，作品可以在浏览器里玩，航线穿过八个梦幻世界。帖子没有交代完整制作流程，因此不能直接写成“纯代码、零素材、没有使用任何视频模型”。

另外两条的路线更明确：Leon Lin 的 [Three.js 小城](https://x.com/LexnLin/status/2121737343287828694)，作者称除声音外画面全部由代码构建；Kevin 的另一段[动画片头](https://x.com/kevin_t_ngo/status/2120540964909711415)，则明确用了 Python 和 Blender。

这些仍是作者展示，不是独立复现实验。但它们指向的变化值得重视：**语言模型越会规划、编程和修改，能被程序表达的视觉内容，就越容易被它接管。**

## Dario 的选择，不等于视频模型的死刑

Dario Amodei 那段关于图像和视频的[访谈剪辑](https://x.com/vikktorrrre/status/2118763685564875020)，很容易被进一步解读成：既然语言模型会越来越强，就没有必要专门训练视频模型。

但核对到的访谈，主要谈的是企业需求和资源取舍。他认为，消费级图像与视频不是当时最优先的方向；如果客户确实需要，也可以采购其他公司的模型。

这不能直接等同于“语言模型变强，视觉训练自然就不需要了”。

不过，从产品竞争看，采购模型这个选项本身就很有意味。

一个通用 Agent 不一定需要拥有最强的视频生成引擎。只要它理解需求、编排流程、选择工具，并把结果交到用户手上，它就可能掌握最重要的客户关系。底层的视频模型依然在运行，但用户记住的，可能已经是安排这一切的助手。

**视频模型还活着，视频产品却可能失去入口。**

## 最先流失的，可能不是电影，而是那些要改十遍的短片

语言模型写动画代码，未必能马上替代写实影视生成。但视频需求从来不只有电影镜头。

产品功能演示、课程原理动画、数据图表、界面录屏式宣传片，都有大量结构明确的内容。它们的难点，往往不是每一帧有多惊艳，而是文字不能错、顺序不能乱、已经定稿的部分不能跟着变。

比如一条产品讲解视频，需要把第三屏的价格改掉，其他字幕、镜头和标志全部保持不动。

如果内容是程序控制的，修改可以落在一个具体对象或一段时间线上。相比重新生成整段画面，这种方式更容易检查，也更容易复用成一整个系列。

这才是成本讨论里更值得关注的部分。

现在还没有足够的同口径账单，可以证明 Fable 路线普遍比视频模型便宜。思考、返工、渲染，以及可能调用的外部模型，都应该算进去。

但买方最终比较的，本来也不该是一次调用多少钱，而是：**交付一条合格成片，总共花了多少钱、改了多少轮、用了多少时间。**

如果一种方案第一次看起来没那么惊艳，却能稳定完成十次修改，它可能比第一次生成就很漂亮、之后每改一次都要重新碰运气的方案，更适合生产。

对视频模型来说，真正的压力就在这里：不需要所有需求都流失，只要那些数量多、修改频繁、标准相对明确的任务开始转移，原来的增长预期就需要重算。

这是一种可能出现的市场压力，不是已经被统计证实的份额变化。

## 未来不是只剩一种模型，而是谁负责哪一部分

程序化视觉和原生视频生成，各自擅长的东西并不相同。

前者容易表达时间线、几何结构、字幕、布局和精确约束。后者更擅长生成丰富的外观、材质、人物动作和摄影感，处理那些很难用规则逐项写尽的视觉细节。

一段解释齿轮如何运转的动画，和一段人物在黄昏街头行走的品牌短片，对模型提出的要求就不同。

更有潜力的方向，是把两条路线接起来：用代码控制字幕、布局和可复用结构，用视频模型生成需要真实质感的片段，再由 Agent 组织、检查和修改。

当然，把它们接起来，不等于所有问题都会自动消失。人物一致性、镜头衔接、生成结果是否遵守约束，仍然是需要解决的难题。

长期来看，结构化视觉和写实生成之间的边界也不会固定不动。更通用的多模态模型，可能把两边能力收进同一套系统。但那意味着视觉生成能力被整合了，不等于视觉数据、视频训练和时间一致性从此没有价值。

## 视频模型不会因为会写代码的 Agent 而立刻消失

更值得担忧的是，视频模型可能从一个用户主动选择的产品，变成 Agent 随时调用、随时替换的工具。

用户提出需求，Agent 决定怎么做。简单的直接写代码，复杂的调用视频模型，需要真实质感的生成片段，需要精确排版的交给程序。最后呈现给用户的，是一个完成任务的系统，而不是某一种模型的能力展示。

到那时，只靠“一次出片很好看”来竞争，会越来越吃力。能不能接受精确控制、稳定修改、保持人物和镜头一致，并顺畅接入其他工具，可能更重要。

Fable 还会继续变强，视频模型也不会原地不动。

**视频模型当然还有未来。真正不稳的，是“用户为了做视频，必须先来找一个视频模型”的未来。**
